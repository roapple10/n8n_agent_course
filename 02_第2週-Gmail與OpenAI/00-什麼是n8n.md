### 什麼是 n8n？

n8n 是一個**開源、可私有化部署的低程式碼 (Low-Code) 自動化工作流程平台**。它的名字讀作 "n-eight-n"（即 "n" + 數字 8 + "n"），寓意是「**通過 8 個連接點將不同的節點 (n) 連接起來**」，實現複雜任務的自動化。

簡單來說，n8n 就像是一個「**數字世界的樂高積木**」或「**現代魔法城堡**」，它允許你通過**拖拽節點、連接流程**的方式，把各種不同的應用和服務（如 Google 表格、Notion、Gmail、Telegram、資料庫等）串聯起來，讓它們自動協作，無需編寫複雜的程式碼。

---

###  n8n 的核心特點

| 特性 | 說明 |
|------|------|
| **圖形化操作** | 不用寫程式碼，像搭積木一樣用滑鼠拖拽節點來構建自動化流程。 |
| **支持私有部署** | 可以部署在你自己的伺服器或電腦上，數據完全由你掌控，更安全 (Self-hosted)。 |
| **AI 友好 (Agentic)** | **2025 重大更新**：內置強大的 **AI Agent Node**，讓 AI 能夠自主規劃任務、調用工具 (Tools)，而不僅僅是處理文字。 |
| **1000+ 第三方服務集成** | 支持 Google Sheets, Slack, Stripe, AirTable, MySQL, Webhook 等超過 1000 個應用。 |
| **半封裝模式** | 既可以用現成節點「無代碼」操作，也能插入 JavaScript/Python 程式碼 (Code Node) 實現自定義功能。 |
| **BYOK 支持** | 支持「自帶金鑰」(Bring Your Own Key)，你可以用自己的 OpenAI / Anthropic / Gemini API Key，靈活控制成本。 |

### ‍ 為什麼說 n8n 是「現代魔法」？

1. **像手工藝品，而非工業製品**  
   n8n 構建的流程更像是「霍爾的移動城堡」——雖然看起來歪歪扭扭、結構複雜，但它能動、能工作，屬於你自己的「魔法造物」。

2. **「雖然我不懂，但它能 work」**  
   在配置 Google Cloud、OAuth 登錄等複雜服務時，你可能並不完全理解背后的原理，但只要流程跑通了，就可以繼續前進。這種「魔法感」正是低程式碼的魅力。

3. **讓 AI 擁有「手腳」 (Embodied AI)**  
   AI（如 GPT）只是一個「大腦」，它不能自己打開 Excel 或發送通知。而 n8n 就是給 AI 裝上「手」和「腳」，讓它能真正幫你做事。

   > 例如：  
   > 你收藏了一篇文章 → n8n 自動觸發 → **AI Agent** 決定：「我需要先總結文章，然後發到 Notion 歸檔，最後通知主人」 → AI 自動調用 Notion 節點和 Telegram 節點。

4. **適合個人和小團隊的「寄生系統」** 
   n8n 不適合做高並發的 C 端產品，但非常適合為現有系統「打補丁」或「加外掛」，比如：
   - 自動同步 CRM 數據
   - 定時生成業務報告
   - 跨平台社群內容分發

###  n8n 能做什麼？（典型場景）

| 場景 | 實現方式 |
|------|----------|
| **自動摘要文章** | Webhook 接收鏈接 → HTML Extract 提取內文 → AI 生成摘要 → 存入 Notion |
| **每日數據報表** | 資料庫查詢 (Postgres/MySQL) → 生成 Markdown 表格 → Slack/Teams 推送 |
| **跨平台發布** | 一次寫作 → n8n 自動分發到 Twitter, LinkedIn, Telegram 頻道 |
| **AI 客服機器人** | 用戶留言 → AI Agent 檢索知識庫 (Vector Store) → AI 回覆 → 發送 Wechat/Line |
| **定時備份數據** | 每天自動導出 AirTable 數據 → 轉換 CSV → 上傳 Google Drive |

---

###  n8n 不適合做什麼？

| 場景 | 原因 |
|------|------|
| **高並發 C 端應用** | 性能、安全性、前端互動體驗無法與原生 App 相比。 |
| **複雜的前端界面** | n8n 是後端邏輯引擎，沒有前端 UI (除了簡單的 Form Trigger)。需配合 AppSmith/Retool。 |
| **極低延遲系統** | 節點執行有一定開銷，不適合毫秒級要求的場景。 |

>  **正確用法**：n8n 做「後端引擎」(Backend)，其他工具（如 Notion, AppSmith）做「前端界面」(Frontend)。

###  為什麼選擇 n8n？對比其他平台

| 平台 | 部署方式 | AI 支持 | 集成數量 | 是否支持 BYOK | 適合人群 |
|------|---------|--------|-----------|----------------|-----------|
| **n8n** |  私有化 / 雲 |  **極強 (Agent+LangChain)** | **1000+** |  是 | 技術愛好者、重視隱私、需要高度客製化 |
| Zapier |  僅雲服務 |  文字為主 | 6000+ |  否 | 預算充足的企業、非技術人員 |
| Make |  僅雲服務 |  尚可 | 1600+ |  否 | 需要可視化邏輯的中型用戶 |
| Dify.ai |  私有化 |  **極強 (RAG專精)** | 較少 (專注 LLM) |  是 | 專注開發 LLM App (如知識庫問答) |

**結論**：
- 如果你要做 **"Workflow Automation"** (連接 A 和 B)，選 **n8n**。
- 如果你要做 **"LLM App"** (如企業知識庫機器人)，選 **Dify**。
- n8n 也可以做简单的 LLM App，但它的強項在於**連接外部工具**。
