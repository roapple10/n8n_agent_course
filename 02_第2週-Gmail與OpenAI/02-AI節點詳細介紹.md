#  AI 節點詳細介紹

n8n 內置了可視化的 LangChain 節點，幫助我們快速接入與使用不同的 LLM 模型，搭建多類型 AI 能力。在熟悉 n8n 的 AI 節點之前，先完成一些必要的科普，再循序講解核心節點與常見場景。

---

## 0. 大模型 AI 接入 n8n 的科普

### 0.1 什麼是大語言模型（LLM）？
大語言模型是一類深度學習模型，目標是理解與生成人類語言。它通過海量文本語料學習語言模式，並據此完成續寫、問答、摘要、分類、糾錯、情感分析、代碼生成等任務。

> 例：輸入一個問題，模型生成答案；輸入一段材料，模型生成摘要；輸入自然語言，模型輸出可執行的代碼等。

### 0.2 僅有 ChatGPT Plus 帳號是否足夠？
不夠。ChatGPT（產品）與 GPT-4/Claude/Gemini 等 API（面向程式的接口）是兩件事。n8n 作為自動化程式，需要對接各家模型的開發者 API。你需要：
- 能訪問海外互聯網（ChatGPT Plus 帳號通常意味著你已具備條件）
- 申請各模型提供商的開發者帳號與 API Key（OpenAI、Google、Anthropic 等）

> 出於合規考慮，本教程不提供具體的開發者帳號註冊指南。

### 0.3 什麼是 LangChain？
LangChain 是一個為大語言模型應用而生的中間層/編排框架，統一了不同模型與工具的接口，降低切換成本與組合複雜度。n8n 將 LangChain 封裝為一組可視化節點，讓我們在編輯畫布上即可完成：
- 選擇/切換不同模型
- 增加 Memory（記憶）
- 連接工具（Tools）
- 串聯多步推理流程

## 1. 節點概覽（Advanced AI 分類）

Advanced AI 分類下包含多種 AI 節點與模板。核心理念：以「鏈（Chain）」為載體連接模型、記憶、工具與外部數據。

本文重點講解兩類高頻節點：
- Basic LLM Chain（基礎鏈）：最簡單、最通用的 LLM 調用節點
- AI Agent（智能體）：在基礎鏈之上引入 Memory、Tool 等組件的進階能力

> 你也可以從 AI Templates 導入官方社區模板，快速獲得可執行的鏈路示例。

---

## 2. Basic LLM Chain

Basic LLM Chain 是對接語言模型的「基礎工作馬」。不強調對話記憶與複雜工具鏈，適合一次性處理類任務：摘要、分類、糾錯、抽取、改寫、要點提取等。

流程簡述：
1) 從上游獲取數據 → 2) 結合 Prompt → 3) 調用 LLM API → 4) 輸出結果

### 2.1 關鍵參數說明

- 必填 Prompt（提示詞來源）
  - Take from previous node automatically：自動取上游最近的聊天消息（通常來自 Chat Trigger）。若你的 Prompt 並非來自 Chat Trigger，建議選擇下方的 Define below。
  - Define below：在本節點中直接編寫 Prompt 文本。

- 必填 Text（當 Prompt=Define below 時出現）
  輸入你希望模型處理的具體內容，可與上游變量結合：
  ```
  請為以下文章生成 5 個備選標題：
  {{ $json.text }}
  ```
  其中 `{{$json.text}}` 為上游傳入的正文。

- 可選 Require Specific Output Format（約束輸出格式）
  啟用後可要求模型以嚴格的結構輸出（如 JSON schema），便於後續節點解析。

- 可選 Chat Messages（當使用 Chat 類模型時）
  預置多輪對話上下文（角色、類型、消息內容），增強語境一致性。適合對話型應用或需要少量上下文記憶的場景。

- 必填 Model（模型子節點）
  Basic LLM Chain 需要你在畫布上添加一個「Model 子節點」，用於實際連接具體模型供應商。

### 2.2 可選模型（子節點）

常見可用類型（隨版本更新可能變動）：
- OpenAI Chat Model / OpenAI Model / Azure OpenAI Model
- Google PaLM Chat Model / Google Gemini Chat Model
- Anthropic Chat Model（Claude）
- Cohere Model
- Mistral Cloud Chat Model
- Groq Chat Model
- AWS Bedrock Chat Model
- Hugging Face Inference Model
- Ollama Chat Model / Ollama Model（本地/私有化）

> 各模型子節點具體參數略有差異，可在子節點面板中點擊跳轉至官方文檔查看。

## 3. AI Agent（進階）

AI Agent 可以視為 Basic LLM Chain 的「擴展版」：
- 通過內部參數選擇 Agent 類型（任務模式）
- 可掛載 Memory（記憶）與 Tool（工具）子節點
- 支持更複雜的推理鏈與工具調用

### 3.1 Agent 參數（任務模式）

不同 Agent 類型對應不同用途與可用卡槽：

| Agent 類型 | 可用卡槽 | 適用說明 |
|---|---|---|
| Conversational Agent | Memory / Tool | 面向多輪對話；在 Basic LLM Chain 基礎上增加記憶與工具 |
| Tools Agent | Memory / Tool | 自然語言操作一個或多個工具（不強調長期記憶） |
| OpenAI Functions Agent | Memory / Tool | 面向 Function Call 的工作流（結構化調用） |
| Plan and Execute Agent | Tool | 規劃-執行範式：AI 自主規劃與串聯工具 |
| ReAct Agent | Memory / Tool | 觀察-行動-反思範式，多步調用與校驗，效果強但可能多次請求 |
| SQL Agent | Memory | 對數據庫進行自然語言查詢與讀寫 |

> 不同 Agent 的必填項略有不同，請在節點參數面板或官方文檔中查看。

### 3.2 Memory 子節點（遺選）

為 Agent 提供短期/長期記憶能力：
- Window Buffer Memory：瀏覽器窗口級短期記憶，免部署，但刷新即失。
- Redis Chat Memory：將對話存入 Redis，支持在刷新後找回，但通常為短期緩存。
- Motorhead：開源記憶服務，支持存儲、向量化與檢索。
- Xata / Zep：第三方長期記憶/向量數據庫服務（免部署，付費/商用）。


### 3.3 Tool 子節點（可選）

讓 Agent 在語言之外「動手做事」，例如：
- Calculator：可靠數值計算
- Custom Code Tool：自定義 JS/Python 邏輯
- SerpAPI：聯網搜索檢索資料
- Wikipedia：百科檢索
- Wolfram Alpha：計算/可視化/學術問答
- Custom n8n Workflow Tool：把另一個 Workflow 變成可調用的「工具」

> 對用戶而言，Custom n8n Workflow Tool 非常實用：可以把你編寫的工作流包裝為 Tool，從而讓 AI Agent 間接調用。

## 4. 發散與模板

- 除本文兩大核心節點外，Advanced AI 下還有 OpenAI 專項節點（繪圖、文件上傳等）與 Question and Answer Chain（針對私有知識庫問答）等。
- 邏輯共性：輸入數據 → 規定 AI 行為（Prompt/Agent）→（可選）記憶/工具 → 獲取結構化結果。
- 模板市場：節點面板 Advanced AI > AI Templates 可一鍵導入社區示例，便於學習與復用。
- 若內置節點無法完全覆蓋你的需求，可使用「LangChain Code」節點直接編寫鏈式邏輯。

---

## 5. 實戰建議（速查）

- 小任務優先 Basic LLM Chain；需要多輪對話/工具調用再上 AI Agent
- Prompt 可模板化並結合上游變量；對結構化輸出使用「Require Specific Output Format」
- 頻繁調用第三方服務時，注意速率限制與重試策略（Wait、Error Trigger）
- 本地/私有化優先考慮 Ollama；合規與成本優先時可選代理商

---

> 提示：若運行環境無法訪問 OpenAI/Google，可使用兼容代理服務；如需生態集成，建議將現有 Workflow 封裝為 Tool 供 Agent 調用。
