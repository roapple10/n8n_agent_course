# 第 5 週｜Telegram 與 LINE 潛客分析：工作流介紹與練習

本週練習把潛客訊息送進 n8n，整理需求、評估跟進優先順序，再把結果回覆給使用者或存入試算表。建議先完成 Telegram 練習，再做 LINE 規則版，最後挑戰 LINE AI Agent 版。

## 啟動本機 n8n

第一次在自己的電腦開課程工作流，先依[Docker Compose 開啟 n8n 教學](Docker%20Compose%20開啟%20n8n%20教學.md)安裝 Docker Desktop 並直接啟動 n8n；本機啟動不需要建立 `.env` 或填金鑰。Telegram 和 LINE 的外部 Webhook，接著依各工作流教材設定 Cloudflare Quick Tunnel。

## Telegram：潛客評分、寫入名單與回覆

### 工作流介紹

Telegram 版示範完整的潛客處理流程：Bot 收到訊息後，n8n 整理欄位並呼叫 Groq 評分，接著把結果新增到 Google Sheets，再私訊回覆給傳送訊息的人。另一個入口可在 n8n Chat 測試；它的回覆只出現在 n8n 編輯器，不會送到 Telegram。

### 練習摘要

1. 依[Telegram 潛客評分工作流教學](Telegram潛客評分工作流教學.md)建立 Telegram Bot，準備 Groq 與 Google Sheets 憑證。
2. 依教材設定本機 n8n 與 Cloudflare Quick Tunnel，讓 Telegram 能連到本機 Webhook。
3. 在 n8n 檢查每個節點與資料來源分支，傳送虛構潛客案例。
4. 在 **Executions** 確認訊息接收、AI 評分、Google Sheets 新增資料與 Telegram 回覆都成功。
5. 延伸練習時修改測試案例，加入資料不完整或需要人工覆核的情況；比較 Telegram 與 n8n Chat 兩種入口。

課堂範例 JSON：

- [上午：Telegram 與潛在客戶評分](課堂練習/上午-Telegram與潛客評分.json)：手動建立潛客資料並練習設定 LLM 評分規則。
- [Telegram 行程與 Sheets 客戶分析範例](課堂練習/上午-Telegram行程與Sheets客戶分析.json)：練習組合 Bot 訊息、分數欄位與高優先級條件。

## LINE Bot：規則評分版

### 工作流介紹

LINE 版讓好友傳來的文字進入 n8n Webhook；工作流驗證 LINE 簽章，只處理文字訊息，再依訊息中的需求、預算和時程等關鍵字計算示範分數，最後用 LINE Reply API 回覆。此版本不呼叫 AI，也不會把資料寫入外部名單。

### 練習摘要

1. 依[LINE Bot 潛客分析工作流](21-LINE%20Bot%20潛客分析工作流.md)建立自己的測試官方帳號、啟用 Messaging API，並把測試官方帳號加入好友。
2. 安裝並啟動 Quick Tunnel，設定 n8n Webhook URL；建立 LINE Channel secret 與 access token 對應的 n8n Credential。
3. 匯入[規則評分工作流](課堂練習/下午-LINE%20Bot%20潛客分析.json)，逐一檢查 Raw Body、HMAC 簽章、IF 條件與 LINE 回覆節點，再依教材 Verify 並發布。
4. 用教材的合成訊息測試，確認 n8n **Executions** 成功、手機收到回覆，並試傳其他內容觀察分數變化。
5. 完成後依教材停用 Webhook、工作流與 Tunnel。電腦或 Tunnel 重啟後須確認 HTTPS 網址並更新 LINE Webhook。

## LINE Bot：AI Agent + Groq 進階版

完成規則版後，再依[LINE Bot AI Agent 潛客分析（Groq）](22-LINE%20Bot%20AI%20Agent%20潛客分析（Groq）.md)匯入並設定[AI Agent 工作流](課堂練習/下午-LINE%20Bot%20潛客分析%20AI%20Agent%20%2B%20Groq.json)。它先保留規則評分，再由 AI Agent 摘要需求、提出下一步和追問，並經 LINE 回覆五項分析。教材逐步說明各節點設定、Groq Credential、模型參數、測試與錯誤排除。

練習時比較兩個版本：規則版輸出較固定且容易追查；AI Agent 版可用自然語言整理資訊，但生成內容可能不同，仍須真人確認。使用合成資料，不要送入真實客戶個資。兩個工作流使用不同 Webhook 路徑；切換版本時依教材調整 LINE Webhook URL 與發布狀態，同一個 Channel 一次只測一個版本。

AI 版實際互動示例：[LINE-AI-Agent-Groq-實際互動.png](教材截圖/LINE-AI-Agent-Groq-實際互動.png)。

## 本週驗收重點

- **Telegram：** Execution 顯示 Bot 收到測試訊息、評分與整理節點成功、Google Sheets 新增一筆資料、Telegram 回覆成功。
- **LINE 規則版：** Webhook 簽章驗證成功，規則分數符合測試訊息，手機收到 LINE 回覆。
- **LINE AI Agent 版：** Groq Chat Model、AI Agent 與 LINE Reply 成功，回覆包含潛客等級、需求摘要、規則分數、建議下一步和追問。
- 任何一個版本測試失敗時，先開啟 n8n **Executions** 找第一個失敗節點，再依對應教材排查；Credential 值不可放入文件、截圖或分享的 JSON。
