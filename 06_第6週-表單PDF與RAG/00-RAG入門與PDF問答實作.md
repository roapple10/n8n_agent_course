# RAG 入門：讓 AI 根據 PDF 文件回答問題

## 學習目標

完成本單元後，你可以：

1. 用自己的話說明 RAG 的用途。
2. 分辨「把文件放進知識庫」和「向知識庫提問」兩個階段。
3. 匯入 n8n 官方範本，設定 Groq 與 Cohere，並讓工作流程回答文件內容。
4. 檢查回答是否有文件依據，並測試找不到答案時會發生什麼事。

## 一、RAG 是什麼？

RAG 是 **Retrieval-Augmented Generation** 的縮寫，中文常翻成「檢索增強生成」。它讓 AI 在回答前，先從你提供的資料中找出相關內容，再把找到的內容交給語言模型整理成答案。

可以把它想成開卷問答：

- **文件**：課本、產品手冊、校務規定或 PDF。
- **檢索**：先在文件中找出與問題最有關的幾段。
- **生成**：AI 參考這些段落，用自然語言回答。

一般聊天模型主要依靠訓練時學到的知識，可能不知道你的最新文件，也可能把不確定的內容說得很像真的。RAG 會先提供文件片段，讓回答有機會根據指定資料作答。RAG 仍可能答錯，所以要核對來源，並用「文件沒有提到時請明確說不知道」等規則限制回答。

### RAG 的六個步驟

1. **載入文件**：讀取 PDF、文字檔或其他資料。
2. **切塊**：把長文件切成較短的文字片段（chunk）。切太大會混入不相關內容；切太小則可能失去上下文。
3. **產生 Embedding**：把每段文字轉成一串數字，稱為向量。語意相近的文字通常會有較接近的向量。
4. **儲存向量**：把向量和原文片段存進向量資料庫。
5. **檢索**：問題也轉成向量，再找出最相近的文件片段。
6. **生成回答**：把問題和檢索到的片段交給聊天模型，請它根據片段回答。

> 本次範本用 Cohere 產生 Embedding，用 n8n 的 In-Memory Vector Store 暫存向量，並用 Groq 上的聊天模型撰寫答案。Groq 在這裡負責「生成回答」；Embedding 由 Cohere 負責，兩者是不同工作，也需要各自的 API 憑證。

### 為什麼不直接把整份 PDF 丟給聊天模型？

文件可能很長，直接把全文放進每次提問會浪費內容與運算，也不容易只挑出相關段落。RAG 會先建立可搜尋的片段，只把最相關的少數內容交給模型。

### RAG 常見應用

- 依公司規章回答員工問題。
- 依產品手冊回答操作問題。
- 依課程講義製作課程助教。
- 依表單回饋或 FAQ 整理常見問題。
- 依 PDF 合約、報告或研究資料搜尋內容（仍需人工確認重要結論）。

## 四、設定模型與憑證

### 1. 設定 Cohere Embeddings

範本有兩個 `Embeddings Cohere` 節點：一個接在寫入向量儲存區的路徑，另一個接在檢索路徑。

1. 點開第一個 `Embeddings Cohere` 節點，建立或選取 Cohere API 憑證。
2. 對第二個 `Embeddings Cohere1` 節點選取同一組憑證。
3. 兩個節點要使用相同 Embedding 模型。本範本預設 `embed-multilingual-v3.0`。

索引文件與查詢問題必須用相容且相同的 Embedding 設定，否則問題和文件向量無法正確比較。

### 2. 設定 Groq Chat Model

1. 點開 `Groq Chat Model` 節點，建立或選取 Groq API 憑證。
2. 範本原始 JSON 使用 `llama-3.3-70b-versatile`。Groq 模型清單會變動；若該模型已不可用，請在節點的模型選單中改選 Groq 帳戶目前可用的聊天模型。也可參考 [Groq 支援模型清單](https://console.groq.com/docs/models)。
3. 儲存後用節點的測試功能確認憑證可用。

## 五、提供練習文件

官方範本中的 `Read/Write Files from Disk` 節點預設讀取 `/tmp/external_data/news.txt`。這個路徑只適用於 n8n 執行環境中實際存在該檔案的情況；在 Docker、自架主機與 n8n Cloud 上，檔案位置和讀取方式可能不同。

### 方式 A：本機或自架 n8n

1. 將一份練習 PDF 放進 n8n 執行環境可以讀取的位置。
2. 開啟 `Read/Write Files from Disk`，把 `File Selector` 改成該環境看得到的完整路徑。
3. 若 n8n 跑在 Docker 容器內，必須使用容器內的檔案路徑；電腦上的路徑不一定能直接使用。
4. 確認執行 n8n 的帳號有讀取權限。

### 方式 B：n8n Cloud 或不能讀本機檔案

使用雲端可存取的檔案來源（例如 Google Drive）下載檔案，再把下載節點接到文件載入節點。也可以用 **Form Trigger** 接收 PDF 上傳，將上傳檔案的 binary 輸出接到文件載入節點。不同 n8n 版本的節點名稱與欄位可能略有不同；檢查輸出是否含有 binary 檔案，再繼續後面的切塊和向量化步驟。

PDF 複製文字的效果取決於 PDF 是否含有文字層。掃描影像 PDF 需要先做 OCR，否則文件載入器可能讀不到內文。

## 六、建立知識庫並提問

### 第一階段：載入文件（索引）

1. 在 `Read/Write Files from Disk` 設定文件路徑，或接上你使用的上傳／雲端下載方式。
2. 確認文件載入節點 `Default Data Loader` 的輸入能收到檔案。
3. 打開 `Recursive Character Text Splitter`，觀察它如何把長文字切成重疊的小段。範本設定 `chunkOverlap` 為 50；初學時先保留預設值。
4. 確認文件載入器連到 `In-Memory Vector Store`，Embedding 節點也連到同一個向量儲存節點。
5. 點選 **Test Workflow**，執行資料載入路徑。確認節點成功完成。這一步是把資料放入知識庫；只匯入 JSON 並不會自動完成索引。

### 第二階段：對知識庫提問

1. 確認聊天路徑的 `In-Memory Vector Store1`、`Vector Store Retriever`、`Question and Answer Chain` 與 `Groq Chat Model` 都有連接。
2. 點選畫布下方的 **Chat**，開啟測試聊天視窗。
3. 先問一個文件明確回答的問題，例如：「文件規定的申請期限是幾天？」
4. 再問一個文件沒有提到的問題，觀察模型是否會猜測。
5. 回到 `Question and Answer Chain` 檢查輸出是否有回答及來源文件資訊。不同範本版本的輸出欄位可能不同；練習時請確認回答依據的片段，而不要只看語氣是否肯定。

> In-Memory Vector Store 適合課堂原型，不是永久知識庫。範本也可能在每次重新建立索引時清空舊資料；請先索引文件，再在同一個 n8n 執行環境中提問。重新啟動服務後若資料不見，重新執行索引流程。正式長期使用時，應改用持久化向量資料庫。

## 七、練習任務

請以一份你選擇的課程規定、校園 FAQ 或產品說明 PDF 完成以下項目：

1. **理解流程**：在畫布上指出載入文件、切塊、Embedding、向量儲存、檢索及生成回答分別由哪個節點負責。
2. **提問測試**：設計 5 個文件有答案的問題，記錄答案和支持答案的文件片段。
3. **拒答測試**：設計 2 個文件沒有答案的問題，觀察模型會否猜測。若會猜測，修改問答鏈的指示，要求只根據檢索內容回答；找不到根據時明確說「文件中沒有找到答案」。
4. **切塊觀察**：改變 `chunkOverlap`（例如 0 與 50）後重新建立索引，觀察檢索到的片段有何差異。每次索引前留意向量儲存區是否清空。
5. **分享結果**：交出工作流程截圖、使用的文件名稱、5 個有答案的問題、2 個無答案的問題，以及你發現的一項限制。

## 八、常見問題排除

- **Cohere 或 Groq 憑證錯誤**：確認建立的是對應服務的 API 憑證，並在每個相關節點選取它；不要把 Groq 憑證放進 Cohere 節點。
- **Groq 模型不存在或不可用**：打開模型下拉選單，選擇帳戶目前可用的模型，再重新測試。
- **找不到本機檔案**：確認檔案在 n8n 執行環境內可見。Docker 容器需要掛載資料夾，且節點使用容器內路徑。
- **PDF 沒讀到文字**：先確認 PDF 可以用滑鼠選取文字。若它是掃描影像，需增加 OCR 步驟。
- **回答沒有根據**：先確認索引流程成功，再確認提問流程使用相同 Embedding 模型、檢索器有連到向量儲存區，並問文件中明確出現的詞句。
- **重新開啟後沒有資料**：In-Memory Vector Store 是暫存型；重新執行索引流程，或改用持久化向量資料庫。
