# 07｜進階技巧

這章不講高大上的概念，只講怎麼把 n8n 用順手。你會看到：什麼時候用 AI 節點、找不到節點怎麼辦、表達式怎麼寫、MCP 值不值得用、怎麼一步步調試、怎麼讓流程更穩不崩，以及怎麼省心維護。

---

## 1. 先想清楚：輸入-處理-輸出

做工作流就像做三明治：
- 輸入：誰來觸發？定時、Webhook、聊天消息、還是手動點一下？
- 處理：中間要做哪些事？條件判斷、循環、數據清洗、讓 AI 總結/分類？
- 輸出：最後要把結果放哪？比如存表、發消息、傳到網盤/數據庫。

小建議：
- 流程複雜就拆開，做成「子工作流」，主流程只負責調度，清爽很多。
- 統一字段名（比如全用英文小寫-中橫線），以後排查不頭疼。

---

## 2. AI 節點怎麼選？

- Basic LLM Chain（大多數情況用它）：
  - 適合「一次性」的文本工作：摘要、改寫、抽取、糾錯、打標籤。
  - 提示詞放在「Define below」，需要結構化就打開「Require Specific Output Format」。
- AI Agent（進階場景才用）：
  - 你需要「多輪對話、調用工具、記憶上下文」的時候，再上它。
  - 可接工具（計算器、搜索、你自己的工作流等）和記憶（Redis、Xata、Zep）。

寫提示詞的順序：角色 → 要求 → 約束 → 輸出格式 → 示例。先用小樣本試通，再推廣。

---

## 3. 找不到節點怎麼辦？用「半開放式」補齊

- Code 節點（JS/Python）：
  - 做輕量數據處理：拼字段、過濾、合併、格式化。
  - 不建議在 Code 裡發 HTTP、讀寫文件，有專用節點更穩。
- HTTP Request 節點：
  - 萬能「插頭」。任何沒內置的 API，都可以先用 Postman 調通，再 Import cURL 進來。
  - 別把密鑰寫死在 Body 裡，統一走 Credentials（更安全）。

常見套路：
- Google Sheets → Set → HTTP(提交任務) → Wait → HTTP(查狀態) → IF(完成沒) → HTTP(拿結果) → Drive/DB/消息。

---

## 4. 表達式其實很好用（別怕）

常用的就幾個：
- 取數據：`$json`、`$("節點名").first().json`、`$input.all()`、`$itemIndex`
- 平台信息：`$workflow.*`、`$execution.*`、`$env`（讀環境變數）
- 時間：`$now.toISO()`、`$today.toFormat('yyyy-LL-dd')`
- 查 JSON：`$jmespath('users[*].email', $json)`
- 小工具：`$if()`、`$ifEmpty()`、`$evaluateExpression()`、`$max()`、`$min()`

心法：表達式做「拿值+小修小補」，複雜邏輯交給 Code 節點。

---

## 5. MCP 要不要用？先用原生節點

- 優先用 n8n 自帶或社區節點。更穩、更快、更好維護。
- 實在找不到對應服務：
  - 你要「讓 AI 調你的 n8n」→ MCP Server Trigger
  - 你要「在 n8n 裡調外部 MCP 工具」→ MCP Client Tool

一句話：能不用就別用，MCP 當應急工具。

---

## 6. 單步調試：每加一個節點就測一下

為啥？
- 出問題能立刻定位，不用「返工從頭找」。
- 用 AI 的節點（比如提示詞）本來就要反覆試，邊試邊改很正常。

怎麼測？
- 點節點上的「Test Step」只跑當前節點。
- 看 OUTPUT 面板：輸入/輸出/報錯一目了然。
- 看不懂錯誤碼？丟給 ChatGPT 解釋一下就好。

測試用例要不要寫？
- 大批量處理/數據質量不穩/用大模型：建議準備 10~20 條樣本，覆蓋正常/邊界/異常。

---

## 7. 跑得穩：節流、分批、重試

- 有輪詢就加 Wait，別 1 秒刷幾十次接口（會被限流）。
- 大數據就分批（batch），比如每次 50 條；需要時並行處理幾批。
- 對超時、限流這類「可重試錯誤」用指數退避（1s/2s/4s…）。
- 需要結構化輸出的 AI，務必要求「嚴格 JSON 輸出」，下游更省心。

---

## 8. 安全與合規：別把密鑰寫進節點

- 所有密鑰走 Credentials 管理。
- Webhook/MCP Server 盡量在內網或加網關（鑑權+限流）。
- 日誌不要打敏感信息，傳給第三方前先「最小化數據」。

---

## 9. 以後維護省心的做法

- 命名規範：英文小寫-中橫線，時間統一時區/格式。
- 版本與回退：重要工作流導出 JSON 存 Git；大變動前打個標籤。
- 常用套路抽出來做成「子工作流/模板」，複用更快。
- 每個實戰都寫個簡短 README：做什麼、用到啥、怎麼跑、容易踩的坑。

---

## 10. 常用「套路」可以直接抄

- 文本 → 結構化：LLM Chain + 要求 JSON 輸出 → Parse JSON。
- 生成 → 輪詢 → 下載：HTTP(POST) → Wait → HTTP(GET status) → IF → HTTP(GET result)。
- 下載 → 存儲 → 發布：HTTP(download) → Drive/S3 → 三方發布（Upload-Post/社媒）。
- 表單當看板：用 Google Sheets 作為「任務面板」，輸入 PROMPT/DURATION，結果回寫 VIDEO/YOUTUBE_URL。
- 生態集成：沒有節點就用 HTTP Request 接第三方服務，必要時把現成工作流封裝成「Tool」給 Agent 用。

## 11. Prompt 快速模板

- 標準骨架：
  - 你是…（角色）
  - 幫我…（目標）
  - 要求…（長度/風格/語言/禁用項）
  - 輸出…（嚴格 JSON/一行文本 等）
  - 示例…（最好給一組）

- YouTube 標題（示例）：
  ```
  你是 YouTube SEO 專家。根據「視頻描述」，產出 1 個 60 字內、可點擊的標題。
  約束：不要過度標題黨；跟輸入同語言；只輸出標題。
  輸入："{{ $('Get new video').item.json.PROMPT }}"
  ```

- 結構化抽取（示例）：
  ```
  從文本中抽取以下字段，嚴格按 JSON 返回；不確定填 null：
  {
    "title": "string",
    "keywords": ["string"],
    "durationSec": "number|null"
  }
  ```

一句話總結：
- 原生節點優先，不夠用再上 Code/HTTP。
- AI 要模板化，提示詞要迭代。
- 每加一步就測一步，慢慢來更快。
- 能複用就複用，能記筆記就寫 README。

把每條工作流當「小產品」養，就會越做越穩，越做越省心。
