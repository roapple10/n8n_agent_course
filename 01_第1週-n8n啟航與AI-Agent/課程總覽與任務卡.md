# 2026 n8n 實作課程

本教材是七週課程的實作主線。每份課堂 JSON 都放在對應週次的 `課堂練習/`，可由 n8n 的 Import from File 匯入；匯入後先讀同週的任務卡，再補上自己的憑證與帳號設定。範本刻意不含 API 金鑰、Webhook 正式網址或真實個資。

## 使用方式

1. 匯入當週 JSON，按節點順序執行並查看每一步的 Input 與 Output。
2. 先完成「必做」，再處理「加分」。任何會寄信、寫入資料或發佈的節點，先改為測試帳號或停用狀態。
3. 將一次成功與一次失敗的 execution 截圖、測試輸入及修正原因交作業。

## 來源與維護

課程設計吸收 [roapple10/n8n-ai-automation-workshop](https://github.com/roapple10/n8n-ai-automation-workshop) 的練習主題與其 n8n-skills 的「節點索引、相容性、模板模式」做法；本資料夾的說明、練習順序與 JSON 為本課程重新整理。功能判斷以 [n8n 官方文件](https://docs.n8n.io/) 為準，更新日期為 2026-09-10。

## 每週任務卡與評量規準

每週作業採相同交付格式：工作流匯出 JSON、執行畫面、測試資料、三句反思（輸入、處理、輸出）。不要提交憑證或含真實個資的 execution data。

| 週次 | 必做 | 加分 | 驗收點 |
|---|---|---|---|
| 1 | 改寫欄位並用表達式產生摘要 | 加入日期欄位 | 每個節點輸出可解釋 |
| 2 | 呼叫公開 API 後只留下需要欄位 | 用 HTTP Request 的 Import cURL 重建 | 能指出狀態碼與失敗原因 |
| 3 | 將 urgent 與 normal 分流 | 把通知改成 Wait 後人工確認 | 兩條分支均有測資 |
| 4 | 驗證表單必要欄位再寫入資料表 | 加上重複提交保護 | 不合法資料不會寫入 |
| 5 | 產生固定 JSON 的分類結果 | 建立人工覆核閾值 | 不依賴自由文字解析 |
| 6 | 文件摘要進入待覆核佇列 | 加入核准後通知 | 有人可中止高風險動作 |
| 7 | 回答附來源與信心分數；為專題加入 Error Trigger 與告警 | 用 Evaluation 測試 10 筆問題，拆出可重用子工作流 | 能判定何時拒答，且有部署與回復檢查表 |

### 專題最低規格

- 觸發器、輸入契約、資料轉換、輸出與失敗處理各自清楚命名。
- 對外寫入、寄送或刪除前有明確的測試環境、核可或 idempotency 設計。
- AI 輸出使用結構化欄位，並保留原始輸入、模型版本、提示詞版本或可追蹤的替代資訊。
